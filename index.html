02 · 项目概要

设计目标与约束

按「设计目标 / 设计约束 / 我的职责 / 成功标准」四项说明。

设计目标

原版装备固定、成长线性。目标是建立以刷宝构筑为核心的长线循环：击杀掉落 → 鉴定 → 构筑流派 → 挑战更高难度。原版只保留战斗、地图与角色升级作为载体；装备生成、词条、材料与货币流转、难度阶梯和终局玩法均为自主设计的独立系统。

设计约束
  • 无源码与官方编辑器：只能修改参数配置表（regulation）、事件脚本（EMEVD）、角色行为脚本（HKS），并通过注入的运行时 DLL 扩展规则。
  • 游戏更新会改变内存布局，需同时兼容 2.7.1 与 2.7.2 两个版本。
  • 需与敌人随机器、无缝联机等第三方模组兼容。
  • 目标用户为普通中文玩家：解压即用、一键启动，异常时自动收集诊断信息。
我的职责

独立开发。负责系统与数值设计、需求拆解与优先级取舍、配置与功能验收、版本发布、宣传视频与玩家反馈闭环。代码实现大量借助 AI 编程助手（Claude Code），详见文末声明。

成功标准
  • 全流程稳定可玩：存档不丢失、无软锁。
  • 强度可量化：成长曲线有模型可查，数值调整有依据。
  • 反馈快速闭环：问题在近期版本修复，每次更新附玩家可读的更新说明。

04 · 系统设计

自主设计的独立系统

战斗、地图与角色升级沿用原版；以下系统的规则、数值与配置均为自主设计，原版没有对应机制，或原有机制被整体替换。配色沿用游戏内稀有度：灰（普通）、蓝（稀有）、紫（史诗）、金（传说）。

系统原版存在的问题暗黑重铸的设计
装备获取装备固定，拾取即定型，重复游玩缺少新的追求掉落未鉴定道具，鉴定时随机生成底材、补正、元素、4 档稀有度与词条
构筑流派差异依赖少数固定装备，构筑空间有限157 个词条族（64 个改变规则）；定向鉴定、许愿石、词条继承与重铸，让玩家朝目标流派推进
经济卢恩只用于升级与购物，后期缺少消耗出口自成循环的装备与材料经济：一键出售、锁定与回购管理装备流转；重铸石、融锻之心、超限锻造石等材料作为消耗出口；暗黑商店以龙心脏与卢恩分区出售；卢恩银行保存货币
难度周目只提高数值，缺少机制变化击败「黑剑」后开放「死亡」「不可能」难度：七道咒痕同时生效，集满碎片可永久反转为祝福；改版头目与魇化精英改变战斗方式
终局通关后只能进入下一周目按地区划分头目池的斗技场试炼、逐波递增的无尽试炼、随头目进度分阶段解锁的暗黑商店
异常状态多数敌人免疫发狂与咒死，咒死又是即死，两种异常几乎无法用于构筑所有敌人都能中：发狂扣 5% 血量并削 30% 架势，咒死改为 60 秒内异常抗性降低
商人暗黑商店接管战灰与法术后，原版商人失去探索价值商人的战灰栏位改为所在地区的未鉴定道具与「小极品」传说武器
支线奖励固定装备奖励无法融入刷宝体系改为同一件装备的史诗版本（补正偏好、词条齐全），最后一环给未鉴定传说，保留原版奖励的辨识度
SYSTEM 01

装备生成与可控随机

针对纯随机掉落导致目标流派难以成型的问题，设计「可控随机」机制：掉落以未鉴定道具投放，鉴定时按底材、补正、元素、4 档稀有度与词条实时生成；玩家可通过一键鉴定、定向鉴定、许愿石，以及装备工坊中的词条继承、武器重铸与超限锻造，逐步逼近目标装备。

  • 运行时生成
  • 可控随机
  • 存档持久化
  • 问题：元素属性容易因敌人对元素的减伤沦为劣势选项武器元素有九种结果、概率均等；总伤害与纯物理持平，拆分属性与纯元素略高，以抵消敌人对元素更高的减伤。
  • 问题：稀有度只体现在攻击力上时，高低档差异不直观战技伤害（×0.7～1.0）、致命一击（×1.2～1.8）与防具减伤按稀有度分层，让稀有度体现在手感上。
SYSTEM 02

词条池与规则引擎

原版没有随机词条，流派差异主要依赖固定装备。为此设计了 157 个词条族的词条池，每族配置数值区间、触发条件与互斥分组；其中 64 个规则改变型词条由运行时规则引擎实现，用于拉开流派差异，触发时配有光效反馈。词条描述沿用原版护符的写法并标注具体数值，装备工坊内置词条百科。

  • 规则引擎
  • 事件总线
  • 触发反馈
  • 词条百科
  • 问题：变体多的词条族容易挤占其他词条的出现机会抽取分两层：先按稀有度决定每个位置是否出词条，再在合格词条中均匀抽取；同组变体合计一份，并按部位补偿，使每个词条整体出现频率一致。
  • 问题：低血流派按血量绝对值结算，收益会随等级膨胀燃血、绝境、残躯、搏命、回光、血瓮 6 个词条成套设计，统一按损失血量的比例结算。
  • 问题：多数敌人免疫发狂与咒死，咒死又是即死，两种异常几乎无法用于构筑改为所有敌人都能中：发狂扣 5% 血量并削 30% 架势，咒死改为 60 秒内异常抗性降低。
  • 设计原则新增的护符效果一律做成词条族，不做固定护符，保证所有效果都进入随机池、可以被刷到。
SYSTEM 03

掉落经济与成长曲线

针对随机装备堆积、误售不可挽回及死亡损失卢恩带来的挫败感，设计独立的经济循环：掉落按区域强度分档投放稀有度，一键出售、锁定与回购管理装备流转，卢恩银行保障货币留存，定向鉴定、重铸与超限锻造作为材料回收出口。受限于测试人员少且以非专业玩家为主，由本人实际体验前期内容确立手感与数值基线，再以此为锚点，用蒙特卡洛战力模型校准后续各阶段。

  • 经济循环
  • 前期基线
  • 蒙特卡洛模型
  • 问题：暗黑商店的购买力需要随推进增长头目奖励的龙心脏与星光碎片按地区递进，追忆头目额外 +2，作为暗黑商店货币。
  • 问题：暗黑商店接管战灰与法术后，原版商人失去探索价值商人的战灰栏位改为所在地区的未鉴定道具与「小极品」传说武器，让商人重新值得寻找。
  • 问题：原版支线的固定装备奖励无法融入刷宝体系改为同一件装备的史诗版本（补正偏好、词条齐全），最后一环给未鉴定传说，保留原版奖励的辨识度。
SYSTEM 04

难度阶梯与终局内容

针对通关后缺乏长线目标、单纯数值加成难以带来新鲜感的问题，设计独立的难度阶梯与终局循环：击败「黑剑」后开放「死亡」「不可能」难度，引入改版头目与魇化精英改变战斗机制；暗黑商店随头目进度分阶段解锁，每次休息一次复活机会降低挫败感，死亡遗失部分未鉴定道具提供风险成本。

  • 难度阶梯
  • 终局循环
  • 风险与回报
  • 问题：高难度只加数值时，惩罚感强而目标感弱「死亡」「不可能」难度中七道咒痕同时生效，在各区域首次击败头目可获得碎片，集满 5 片即将该咒痕永久反转为祝福，把难度惩罚转化为可追求的长线目标。
  • 问题：高难度会改变整个世界状态，误入代价大入口设在击败「黑剑」玛利喀斯之后，进入需二次确认且不可逆；同一存档中已全部反转咒痕的角色可跳过门槛。
  • 问题：为高难度另做敌人内容成本高，玩家也难以预判魇化精英直接带上玩家装备中已有的词条，不新增词条，让熟悉的效果反过来成为威胁。
  • 问题：装备成型后缺少继续挑战高难度的动力超限锻造石只在高难度掉落，每个头目每档只掉一次（「不可能」一次掉两颗），以掉落规则控制追求节奏。
  • 问题：终局需要可重复、有节奏变化的挑战斗技场试炼按地区划分头目池，魇化精英波次中 20% 的精英换成击杀后回复圣杯瓶的粪金龟；无尽试炼由魇化精英与头目轮流出场，每波血量 +5%。
SYSTEM 05

技术方案与工具链

采用数据驱动方案：启动器（Python + WebView2）每局生成参数配置表、EMEVD 事件与 HKS 行为脚本并启动游戏，同时负责存档定时备份、在线与离线增量更新、崩溃检测与诊断包导出。开发侧有游戏内测试面板、帧耗时统计与数值模型，354 个单元测试用于功能验收。

  • 配置生成
  • 功能验收
  • 增量更新
  1. 启动器玩家点「启动」或「重新随机」，读取难度和设置。Python · WebView2
  2. 生成游戏数据读原版数据表，生成装备底表、掉落表、词条、事件脚本、行为脚本和中文文本。多进程并行
  3. 叠加加载不改游戏目录，启动时由注入式加载器把改动叠上去。regulation · EMEVD · HKS · msg
  4. 运行时鉴定时生成装备，规则引擎每帧处理机制词条，游戏内界面提供装备工坊。Rust DLL · hudhook
  5. 反馈崩溃时自动导出诊断包，玩家在反馈表登记，进入下一个版本。诊断包 · 反馈表

新版本通过在线或离线增量更新包发给玩家，旧存档里的装备随版本一起迁移。

案例 1 · 技术方案

启动器被安全软件误报：从规避特征到替换技术栈

问题

部分安全软件（如火绒的「系统加固」）在玩家打开启动器、点按钮、崩溃检测时弹出「利用 PowerShell 执行可疑脚本」，玩家会以为整合包带毒。

设计约束

不能要求玩家去改安全软件设置；启动器同时负责启动、数据生成、诊断包和更新，不能停更去重写。

  1. v0.10.72026-11-14
    决定
    先去掉最像恶意脚本的几个特征：不再隐藏窗口启动、不再传编码过的命令、不再从系统临时文件夹运行；诊断包也不再读取杀毒软件的记录。
  2. v0.10.1411-18
    观察
    仍有安全软件把整合包误报成病毒。
    决定
    启动器整体从 PowerShell 改写为 Python（随包带运行环境）+ WebView2 网页界面，不再经过 Windows 的脚本程序；界面和用法保持不变；去掉「经典界面」，只维护一套。旧脚本保留下来做对照测试。
    结果
    触发这类拦截的条件（运行 PowerShell 脚本）不再存在；玩家不需要重新学习操作。
复盘

第一次只改了特征，规则一变就可能再被拦。第二次的迁移成本高得多，但处理的是根源。以后遇到「玩家信任」类问题，会更早评估是否直接换掉触发条件。

案例 2 · 数值验证

成长曲线：以前期手感为基线，用模型校准后续阶段

问题

测试人员少且以非专业玩家为主，仅凭反馈难以完成数值校准；随机装备、157 个词条与敌人随机叠加后，强度也无法单靠手感判断。

设计约束

模型必须和游戏里生成装备的逻辑一致，否则结论没有意义；改一次数值后要能很快重跑。

  1. 基线开发早期
    做法
    由本人实际体验前期内容，确立开局阶段的手感与数值基线，作为后续推演的锚点。
  2. 建模2026-10-30
    做法
    以前期基线为锚点，调用游戏内鉴定用的同一份代码导出装备池（每类每档 400 件），用蒙特卡洛模拟角色按流程获取装备、配装与战斗，推演并校准后续各阶段；对比「原版 / 不随机敌人 / 随机敌人」三种模式，输出成长曲线与词条强度排名。
    提速
    Python 版 200 轮要 575 秒，移植到 Rust 后 20 秒；两版的词条排名一致，其余差异在随机种子误差以内。
  3. v0.911-04
    定位
    模型显示幽影之地后期近战战力约为原版 12 倍，法术仅 2～3 倍，存在成长失衡。
    决定
    引入法器补正系数：生成的法杖、圣印记补正乘以按稀有度随机的系数（普通 0.7～1.3、稀有 0.9～1.5、史诗 1.1～2.1、传说 1.5～2.5，呈中间集中分布）。
  4. v0.9.711-06
    决定
    法球类词条的伤害改为按手上法器的法术补正计算，强化、补正和加点都会影响。
  5. v0.10.1811-21
    决定
    弓也加上按稀有度定范围的补正倍率，远程流派跟上。
未解决 / 下一步

0.10 版的反馈里仍有「前期成型速度太快」。模型现在看的是全流程曲线，开局几个小时的掉落节奏还没有单独校准，这是下一步要补的。

案例 3 · 兼容与边界

第三方随机器导致的软锁：先止损，再查根因

问题

开敌人随机时，唤灵蜗牛被换到尤米尔的头目场地，两只随从打完只亮血条，蜗牛本体不出现，战斗无法结束（软锁）。

设计约束

敌人随机由第三方随机器生成，不随整合包分发，我们只能改交给它的预设；诊断包里没有那一份事件脚本。

  1. 排查2026-11-20
    观察
    运行日志显示蜗牛在场地里，但从没被激活。外部报告提出的两个原因，对照参数后都排除了。更可能的原因是随机器合并事件时套用了场地模板，关掉了它的 AI 和碰撞，但没有那一局的事件文件，无法证实。
  2. v0.10.1611-20
    决定

08 · 整体复盘

32 天、58 个版本之后

做得好的
  • 版本节奏快（32 天 58 个版本），每版附玩家可读的更新说明。
  • 数值模型与游戏共用装备生成代码，模型结论可直接转化为数值调整。
  • 存档安全优先：定时备份、离线增量更新、旧装备数据随版本迁移。
  • 崩溃自动导出诊断包，远程定位问题不依赖玩家描述。
要改进的
  • 游戏内验收滞后于版本节奏：部分修复仅有单元测试覆盖，实际效果依赖玩家确认。
  • 和其他模组、叠加软件的兼容问题定位慢：第五护符槽偶尔不生效，根因未明，目前靠运行时补挂兜底；部分玩家打不开装备工坊，已定位到界面钩子被帧数显示类叠加软件抢占，尚未修复。
  • 前期成长节奏仍有反馈，战力模型尚未单独校准开局阶段。
